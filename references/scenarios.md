# 六大模式规则与权重表

> 每日先选一个**主模式**（决定语气与呈现），再叠加**修正项**（微调候选结果）。

## 主模式选择

按优先级从上到下判断，命中即停。

| 优先级 | 条件 | 主模式 |
|---|---|---|
| 1 | 用户明确说"来不及/ 迟到 / 快点" | 赶时间 |
| 2 | 用户主动想探索或无聊 | 盲盒 |
| 3 | 可用时间 ≤ 20 分钟 | 早八人格 |
| 4 | 默认 | 早八人格 |

## 主模式详解

### 1. 早八人格（主打）

根据用户「可用时间」推断今日精神状态，输出一句人格描述 + 一个对应套餐。

人格描述要具体、有画面感，不要写成励志口号。好的例子：「今天你有18 分钟，够坐一会儿 —— 悠哉鉴赏家上线」。差的例子：「根据您的可用时间为您推荐营养均衡的套餐」。

人格定义见 `references/personas.md`。

### 2. 赶时间

核心是切换到 `locker-in` 外带柜通道，实现「路过即取、免排队」。

动作：
1. 立即确认用户最晚到店时间
2. 优先选择出餐快、便于携带的组合（避免复杂选配、多现做）
3. 算价时传 `takeWayCode=locker-in`
4. 提示语强调「不用进店，报取餐码拿走」

### 3. 盲盒

三选一卡牌。用户从中挑一张即完成选择，全程不需浏览菜单。

卡牌内容必须：
- 在预算区间内（硬约束）
- 每张卡有明确的取餐时间预期
- 三张卡之间有实质差异（不是三份差不多的东西）

可选中后支持**无成本更换一次**，防止翻车。

## 修正项

修正项在主模式选完候选后叠加微调，不改变呈现风格。

### 时间锁

倒排逻辑：

```
出餐准备 = 门店出餐缓冲（默认 3 分钟）
取餐时间 = 用户到店时间
下单截止 = 到店时间 - 出餐准备 - 安全余量（1 分钟）
```

若 `下单截止` 已过（即已无时间下单），立即切换赶时间模式并告知用户。

向用户明示时间预期：「你 8:22 到店，现在下单预计 8:25 出餐」。

### 天气修正

| 天气 | 修正方向 |
|---|---|
| 降雨 / 降雪 | 热饮权重上调，优先热食；提示就近取餐、减少淋雨步行 |
| 低温 | 高热量主食权重上调 |
| 高温 | 冷饮权重上调 |
| 晴好 | 正常，不修正 |

天气作为背景信号自动混入，不作为独立模式暴露给用户。

### 预算护栏

硬约束：任何方案的到手价必须落在 `[下限, 上限]` 区间内。

执行顺序：
1. 先按模式生成候选
2. 算价
3. 超上限 → 降级（去掉非必要加购、换更小规格）后重算
4. 低于下限 → 提示可升级，用户确认后再改
5. 反复两次仍越界 → 直接给出区间内的替代方案并说明原因

叠加优惠券要在预算校验**之后**进行，优惠后的到手价才是最终判断依据。

## 候选打分表

主模式产出的候选按以下权重排序：

| 维度 | 权重 | 说明 |
|---|---|---|
| 时间匹配度 | 0.35 | 出餐时间是否匹配用户到店时间 |
| 预算契合度 | 0.25 | 到手价在区间内的位置，越贴近预算上限越受欢迎 |
| 口味匹配度 | 0.20 | 基于用户历史订单与偏好 |
| 健康度 | 0.10 | 热量与营养（仅在用户未关闭时生效） |
| 天气契合度 | 0.10 | 与当前天气是否搭配 |

用户未提供历史数据时，口味匹配度按品类通用分处理，并在建议中说明「按通用偏好推荐」。

## 兜底策略

| 情况 | 处理 |
|---|---|
| 用户明确要自己选 | 展示精简菜单（不超过 8 项），不坚持推荐 |
| 无历史数据 | 基于时段给出通用推荐，说明是首次使用 |
| 门店无早餐供应 | 告知实际可售品类，调整推荐方向 |
| 所有候选都超预算 | 明确告知最低可到手价，让用户决定是否调整区间 |
| 工具调用连续失败 | 如实告知失败原因与已尝试的步骤 |

## 交互原则

- **默认一次决定**：不摆十个选项
- **给出理由**：每���推荐附一句为什么，理由基于真实输入（时间、天气、历史）
- **可无成本更改**：用户对结果不满意时，直接换，不加阻力
- **数字来自接口**：所有价格、时间、热量均取自MCP 返回值
