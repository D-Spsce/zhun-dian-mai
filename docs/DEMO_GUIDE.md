# 准点麦 · 演示物料制作指南

> Star 是本项目唯一的排名依据。本文件指导制作 README 首屏动图与演示视频。
> 目标：让陌生人 15 秒内看懂「这是什么、解决什么」，进而愿意点 Star。

---

## 一、README 首屏动图（最重要）

### 为什么必须做

GitHub 首屏动图是被Star 概率最高的元素之一。榜单前排项目普遍有。
纯文字 README 在信息流里几乎无人停留。

### 规格

| 项 | 规格 |
|---|---|
| 格式 | GIF |
| 尺寸 | 900 × 500 px（README 首屏适配） |
| 时长 | 12-18 秒 |
| 帧率 | 30fps |
| 体积 | **控制在 3MB 以内**（超过 5MB GitHub 会显示警告） |
| 循环 | 无限循环 |

### 分镜脚本（5 幕）

#### 幕1：痛点（0-3 秒）

**画面**：手机屏幕特写，微信小程序菜单页面，商品列表快速滚动

**字幕**：
```
早上 8:00 出地铁口
选餐 2-3 分钟，付款 1 分钟
```

**设计要点**：这一幕必须让人「认出自己」—— 用真实的小程序界面截图（可打码）。

#### 幕 2：触发（3-5 秒）

**画面**：手机从口袋掏出，屏幕亮起，直接跳到「准点麦」推荐卡片

**字幕**：
```
出闸那一刻，时间已经帮你缩小了选择范围
```

**设计要点**：从菜单页直接切到推荐卡片，制造强对比。

#### 幕 3：早八人格（5-9 秒）

**画面**：卡片翻转动画 —— 「Deadline 战士」人格卡展开，显示套餐

**字幕**：
```
可用时间 9 分钟
→ Deadline 战士
→ 吉士蛋堡 + 中可
```

**设计要点**：**人格卡翻转是全片最有记忆点的画面**，要做出来。

#### 幕 4：取餐方式切换（9-12 秒）

**画面**：两个取餐方式图标并排，`eat-in` 灰，`locker-in` 高亮

**字幕**：
```
赶时间 → 外带柜通道，报取餐码就走
```

**设计要点**：这是差异化亮点，必须展示。

#### 幕 5：结果（12-15 秒）

**画面**：取餐码 + 时间轴「8:22 到店 → 8:25 出餐」

**字幕**：
```
一次决定，准点到达
```

**设计要点**：结尾定格，附项目名与 Star 引导。

### 制作方式

**方案 A（推荐，快）**：用 Screen Studio / OBS 录屏 + Figma/Snagit 标注字幕
- 录屏 → 剪辑 → 加字幕 → 转 GIF
- 优势：真实界面有说服力

**方案 B（无 MCP 也能做）**：用 Figma 画出三张界面原型，再做翻转动效
- 优势：不受网络限制，界面更干净
- 劣势：少了「真实感」

**方案 C（最快）**：直接用 README 里的表格 + 纯文字，做「终端风格」动图
- 把对话记录导出成终端截图，滚动播放
- 优势：30 分钟能完成，程序员受众接受度高

⚠️ **注意**：动图里的所有价格、门店、餐品信息**必须来自 MCP 真实返回**，或使用明确的示例标注。不能编造真实菜单价格。

## 二、演示视频脚本（60-90 秒）

> 用于 B站 / 知乎 / 即刻 / V2EX 附视频。短视频平台可裁剪为 30 秒版本。

### 脚本结构

#### 0-5 秒 · 钩子

**画面**：地铁站台，手持手机走出闸机
**旁白**：「每天早高峰，地铁口出来第一件事是什么？点早餐。」

**字幕**：早上 8:00，出地铁口，要吃早餐

#### 6-15 秒 · 痛点放大

**画面**：分屏左右 —— 左：菜单滚动 + 犹豫光标；右：支付多步界面

**旁白**：「选餐纠结两分钟，付款再花一分钟。十分钟就没了。」

**字幕**：选餐 2-3 分钟 · 付款 1 分钟

#### 16-30 秒 · 解法登场

**画面**：画面一分为二，左侧是「传统点餐」，右侧是「准点麦」

**旁白**：「换个思路 —— 你其实不缺选择，你缺的是时间。」

**字幕**：时间才是第一变量

#### 31-50 秒 · 六大模式速览

**画面**：快速切换六个模式卡片（每个 3 秒）

**旁白**：
「早八人格、时间锁、天气修正、赶时间、预算护栏、盲盒。
出门前看一眼，方案就定好了。」

**字幕**：六种模式，一次决定

#### 51-65 秒 · 技术亮点

**画面**：代码/工具调用示意 + `takeWayCode` 两个取值高亮

**旁白**：「赶时间模式不是概念 —— 麦当劳的外带柜通道真实存在，`locker-in`，报了取餐码就走，不用进店。」

**字幕**：`takeWayCode = locker-in` · 外带柜通道

#### 66-80 秒 · 结尾

**画面**：取餐码 + 时间轴完成态，然后是项目主页

**旁白**：「出闸到取餐，一次决定。准点麦，开源了。」

**字幕**：GitHub 搜索 zhun-dian-mai

## 四、素材合规注意

| 要求 | 说明 |
|---|---|
| **不出现竞品名** | 规则明确禁止与其他品牌对比，推广文案与素材中一律不得出现 |
| **价格必须真实** | 若使用 MCP 返回的真实菜单，保留来源；否则明确标注「示例」 |
| **不含 Token** | 截图前检查终端与代码，务必遮挡 |
| **不承诺效果** | 不写「一定能省 X 元」这类无法验证的承诺 |
| **GitHub 不刷Star** | 禁止机器人、批量账号刷榜，违规会取消资格 |

## 五、执行建议（今天完成）

| 优先级 | 事项 | 预估时间 |
|---|---|---|
| 🔴 P0 | README 提交（**不带动图也能提交，先占位**） | 20 分钟 |
| 🔴 P0 | 报名 Issue 提交 | 10 分钟 |
| 🟡 P1 | 动图制作（方案 C 或 A） | 1-2 小时 |
| 🟢 P2 | 演示视频 | 2-3 小时 |

**关键策略**：**先提交，再优化。** 报名 Issue 提交后项目即进入排行榜统计，之后补动图、改进 README 都是增量，边际收益递减；而晚一天报名则是实打实损失一天竞争时间。
